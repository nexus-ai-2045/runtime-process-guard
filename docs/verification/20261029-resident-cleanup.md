# メニューバー観測と接続終了回収の検証

## 対象と範囲

2026年10月29日、`macOS`のローカル実機で検証。比較元は`main`の`79ae58c`で、実装対象はこの記録と同じ配送用のソースです。元の署名済みアプリ、既存の未管理プロセス、常時接続サービス、進行中の作業へ終了信号は送っていない。試験用に起動した対象と、本機能の旧観測アプリだけを操作した。個人のパス、会話本文、認証値、原ログはこの記録に含めない。

## 自動回収の比較

同じ32メビバイトの作業領域を持つ標準入出力サーバーを、自動管理なし／ありで交互に各5回実行した。試験サーバーは応答後も意図的に残留する。実サービスや`Codex`全体の代理とはしない。

| 項目 | 管理なし | 要求追跡付き管理 |
| --- | --- | --- |
| 要求中の保持 | 5回すべて保持 | 5回すべて保持 |
| 応答完了・入力終端後の残留 | 5回 | 0回 |
| 起動中央値 | 34ミリ秒 | 374ミリ秒 |
| 起動範囲 | 34〜40ミリ秒 | 367〜378ミリ秒 |
| 対象サーバーの停止前`RSS`中央値 | 約48.5メビバイト | 約48.5メビバイト |

管理なしの試験残留は、採点後に試験所有者が片付けた。管理付き対象は自動終了と所有台帳解除を確認した。`RSS`は共有メモリを含むため、物理的な空きメモリが同量増えたという証明ではない。管理ラッパーの起動コストも増えており、既存の全接続へ一括導入する根拠にはしない。比較中も他の作業は維持したため、数値は本環境の標本であり普遍的な性能保証ではない。

## 観測アプリの負荷

ネイティブのメニューバーを約65秒の有限試験で起動した。終了処理を含む計測区間は約68.6秒。観測2回、同時観測最大1、終了時の観測プロセス残存0、観測実行エラー0。`OS`権限による不完全観測2回を正常件数とは分けた。

- 常駐`RSS`中央値：約35.7メビバイト。共有メモリを含む。
- アプリ自身の`CPU`時間：約0.273秒。
- 回収済みの観測用子プロセスの`CPU`時間：約0.301秒。
- 合計`CPU`時間：約0.574秒。区間平均は単一コア換算で約0.84%。

これは一回の有限試験であり、睡眠復帰、長期運用、本人の画面での操作受入、元のアプリの操作待ち時間の改善は別途確認が必要。

## 検査と再現方法

全`Python`試験は`437 passed, 6 skipped`。スキップを`Windows`実機受入済みとは扱わない。ログイン起動の一時ディレクトリ試験15件、`Swift`表示入力10事例、新旧能力表示の有限試験、同じ状態ファイルへの二重起動拒否を確認した。

```sh
python -m pytest -q
python -m pytest -q macos/MenuBar/test_install_login.py
./macos/MenuBar/build.sh
python macos/MenuBar/verify.py
```

独立レビューで見つかった出力読取りと台帳登録の競合を修復し、実パイプによる再現は停止信号なしとなった。停止済みイベントによる待機ループの空回りも回帰試験で防いだ。状態モデルは`guard`内の読取り登録の隙間を表し、旧経路では3遷移の反例、修復経路では7状態の検査が成立した。外部サーバーが将来生成する出力の不存在まで保証するモデルではない。

`GitHub`の既存検査は`Python`向け。ネイティブビルド、表示、ログイン起動はローカル実機で検証した。実際のログアウト・再ログインは他作業保護のため実施していない。署名済み本体の反復読込みや描画負荷が解消したとは報告しない。

## 公開レビュー後の修復と未完了の検査

レビューの重大指摘3件を修復した。ログイン登録の控えは自動読込み対象外へ保存する。登録名、代替名、旧キャッシュの表示情報は秘匿処理を通す。要求追跡付き管理では、利用側の入力終端を記録しても、処理中の要求と出力が排出されるまでサーバーへ入力終端を渡さない。

非同期サーバーが入力終端で未完了処理を取り消す再現試験は、修復前の失敗と修復後の成功を確認した。関連する接続検査は`79 passed, 6 skipped`、秘匿・一覧・常駐の検査は`75 passed`、ログイン登録は`16 passed`。独立したコードレビューと安全性レビューに追加の重大指摘はなかった。

修復後の全体試験は`459 passed, 6 skipped, 1 failed`。変更していない従来の観測経路で終了状態の検査が失敗し、同じ試験の再確認では応答待ちも時間切れになった。直後の実機は8コアに対し負荷平均約162、スワップ使用約22ギビバイトだった。負荷との因果関係は未確定であり、環境を理由に合格とは扱わない。過負荷時の繰返し実行は止め、安定した実機での全体再検査を残務とする。先の全体成功は修復前の結果であり、今回の修復後の全体成功を意味しない。
