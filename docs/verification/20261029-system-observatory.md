# `PC`全体の観測とチャット対応の実装検証

## 実装した範囲

`resident observe --scope system`と専用の状態形式を追加した。旧`resident snapshot`とその状態は維持する。全体観測は既存の一回のメタデータ列挙、秘匿、世代照合、対応証拠、集計を再利用する。

ネイティブ表は、観測できた全行の検索・並べ替え、登録チャット、種類別の本数・合計負荷を表示する。親の`OS`上の`PID`と、確定した表示ツリーの親を区別する。登録名だけで実行`PID`を推定せず、直接対応・関連のみ・未対応を表示する。チャット名の読取りは既存のメタデータ取得を利用し、現在は1000件上限と省略の可能性を明示する。

一覧の全行は保護し、任意`PID`を停止する操作は追加していない。自動整理は既存`guard`が起動から所有する専用接続の終了処理に限定される。実際の製品接続は未登録であり、能力表示と採用状態を混同しない。既存の`Discord`・`Orca`・進行中の作業へ停止信号やアーカイブ操作は行っていない。更新したのは、このタスクで設置した観測アプリだけ。

## 試験とレビュー

- 関連`Python`試験は106件成功。
- `Mac`上の`Python`全体試験は491件成功、6件スキップ、33.37秒。スキップを別`OS`の実機受入とはしない。
- `Swift`の最適化ビルド成功。既存と新形式の18事例、単一起動、実際の表での検索3行から2行、`PID`昇順、登録・集計表、表示状態を確認した。
- 同じ観測標本を追加で2回通知しても表の再構築が1回であることを検査した。
- 独立した`Python`レビューと安全性レビューで見つかったキャッシュ入力境界を修復した。破損キャッシュによる例外と、旧集計の文字列の無加工転載は、修復前5件失敗、修復後成功で確認した。
- 再起動で単調時計が小さくなる場合は、旧起動世代の比較基準を捨てて新規観測へ進む。入口を通す再起動試験を修復前失敗、修復後成功で確認した。
- 同じ起動世代の不正・未来のキャッシュは保存したまま不明応答にする。検査器や秘匿を無効にして通していない。

以前の過負荷区間では`Mac`全体試験に1件の失敗があった。今回は全体成功を確認したが、以前の失敗原因の確定や、再発しない保証とは扱わない。

## 実データと画面

実ツールのチャットメタデータ、マーカーの実体、開いたファイル記述子、実行プロセスと補助プロセスの世代を照合し、1チャットの直接対応と補助プロセスの関連を登録した。登録は期限付きで停止権限を付与しない。既存の他チャットへ一括送信したり、名前から対応を補ったりしていない。

実データの全件表を専用アプリの画面から読み戻した。画面で726件と取得不可183件、3種類の表、検索欄、更新ボタンを確認した。`OS`の列挙は原子的な完全捕捉ではない。画面読取りツールがアクセシビリティ項目を省略する場合と、アプリの全行数を区別した。

有限試験の終了時には、表の行数と同じ標本のプロセス行数717件が一致した。登録表1001行は登録1000件と上限警告1行で、全チャット取得済みとはしない。実画面での検索操作はアプリ状態変化のため停止し、成功扱いにしなかった。検索・並べ替えの動作は別の合成データで実際の表を使って確認した。

いずれも2026年10月29日の同じ`Mac`での有限測定。隣の作業は維持し、負荷を揃えた交互の比較ではないため、高速化率や改善率は算出しない。`CPU`は一つのコアを100%とする。

最終区間は画面検査を行わず、表を開かずに実`AppKit`のメニューバーを起動した。全体観測686件、取得不可163件、同時観測最大1、観測プロセスの実行エラー0、終了時の観測子残存0、部分観測1回だった。収集自体の壁時間は約255ミリ秒、`CPU`時間は約204ミリ秒、収集器の`RSS`標本は約33.2`MiB`。観測子の起動・補助処理を含む`CPU`は、表の0.543秒に含めた。

`RSS`は共有メモリを含む。収集器の`RSS`標本は最大値や監視全体の同時ピークではない。通常常駐の`CPU`目標はこの区間で満たしたが、操作中の1%目標と監視全体100`MiB`の同時ピークは達成確認済みとしない。

測定と修復を通じて、セルを再利用し、検索・並べ替え時は対象の表だけを再処理するようにした。同じ標本の状態通知で全表を作り直す処理も削除した。これらの機械的な改善と、操作時の性能達成は別の結果である。

## ローカル反映と限界

既存の専用仮想環境へ`Python`の変更を反映し、生成アプリとログイン起動先を新版へ切り替えた。切替は既存の安全な登録器を利用し、旧登録の控えは自動読込み対象外に保存する。`Codex`本体や`OS`の設定は変更していない。実際のログアウト・ログインは他作業のため未実施。

全`PID`のチャット対応を確定したわけではない。`Electron`の画面と描画`PID`を外部から確実に結ぶ正式な経路、未登録の実行カーネル、`Discord`・`Orca`固有の対応は未確認として表示する。処理中の認定がない行は、低`CPU`でも使用状況不明として保護する。

高頻度の選択対象サンプリングと6標本の履歴は未実装。検索・並べ替え・タブ操作で収集を増やさず、通常120秒、圧迫・部分・失敗時300秒で動く。長期の負荷、睡眠復帰、別`OS`の実機、本人による操作受入、`Codex`本体の操作待ち時間と反復読込みの解消は別の残務である。
