# ADR-0003: 必要な接続の起動上限と所有ライフサイクル

- 状態: ローカル実装を採用、実runtime適用は受入待ち
- 日付: 2026-10-02
- 関連: ADR-0001、ADR-0002

## 目的と責務

主眼はMCPの必要時起動と、重複・残留によるPC負荷の抑制である。設定棚卸しやtool定義の遅延ロードだけでは達成としない。
本repositoryが起動前判定、接続の所有、終了、postflightを担当する。利用元が必要なMCPの選択と実効設定を担当する。
モデルAPI、APIキー、追加API課金、Codex App Server、固定間隔の外部killは追加しない。

## 採用判断

今回の起動単位は作業・接続。初期予算は同一server identityが2、共有registryの管理対象全体が4である。
上限指定はopt-inで、無指定の既存CLIは互換維持する。上限付きregistryはv2として旧binaryからの書込みを拒否させる。
同じregistry内で予算を変更したり、無指定呼出しで上限を迂回したりしない。移行は利用元を停止し、既存接続を保全した上で別途レビューする。

生存ownerを確認し、古い記録の整理、上限確認、起動枠の予約を一つのロック内で行う。資源判定に通っても予約できなければ起動しない。
上限超過は新しい起動だけを終了コード20で拒否する。guardは再試行しない。既存接続を停止して枠を空けない。
期限切れだがowner生存中のleaseを整理しない。PIDと作成時刻を確認してowner消滅・置換が確定した記録だけを整理し、読取不能はunknownで止める。

直接の子が先に終了しても、所有Job内の孫とstdout中継が生きていれば接続を継続する。
終了条件はEOF、中継終了、確認済み接続owner消滅。親shellの終了や無通信を終了理由にしない。
明示するclient ownerはPIDとtimezone付き作成時刻の組で、利用元が接続ownerを一次証拠で確定して渡す。
未指定の既存起動ではEOF互換を保つが、owner監視による終了保証はしない。実pilotではowner確定不能を停止条件とする。

graceは30秒を維持し、期限後は自身が起動したowned Jobだけを回収する。
heartbeatの再試行はロック競合のみ、最大3回かつTTL内。破損・所有者不一致を自動修復しない。
postflightのgoneは所有Job内の終了証明であり、別仲介経路の残留まで証明しない。実機受入で外部観測を併用する。

## 4AIレビューの採否

- 採用: 起動上限の欠落、正常並行接続と旧世代リークの区別、guardを含む総負荷測定、direct stdioとPlugin同梱の区別。
- 再現試験後に修正: 子の早期終了と孫の誤停止、owner消滅とpipe残留、heartbeatロック競合。
- 未確認として保留: 特定コマンドのJob外breakaway、Codex製品のlazy startup利用可否。
- 対象外: 汎用stdio proxy、通信空白によるidle終了、未知PID・一般Nodeの名前一致kill。

## 完成条件と復帰

単体試験・Windows実プロセス試験・独立レビューと、実Desktop受入を別々に記録する。
1種類のdirect stdio MCPで5回smoke、2接続の隔離、上限拒否、30回反復、レビュー済み再起動前後を確認する。
未選択時の未起動、終了後の残留なし、保護接続の生存、世代蓄積なしを必須とする。上限はこのregistryへ配線された対象だけに効く。
設定差分、実効owner、保護対象、元の設定への復帰手順をレビューしてからruntimeへ適用する。
旧registryを読み替えて強制的に新予算へ切り替えず、v2と旧binaryを混在させない。unknownを成功に読み替えない。
