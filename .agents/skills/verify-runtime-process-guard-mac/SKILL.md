# マック版の実機検証

## 起動と事前確認

リポジトリのルートで、既存の観測アプリが動いていないことを `ps -axo pid=,comm=` で確認する。実行ファイル名が `RuntimeProcessMenuBar` の既存個体があれば、新規起動を見送る。既存個体を終了しない。

[マック版の説明](../../../macos/MenuBar/README.md) に従い、`./macos/MenuBar/build.sh` と `python3 macos/MenuBar/verify.py` を順に実行する。既存検証は合成データで表、検索、プロセス番号順を確認する。実際のメニューと負荷順は [機能マップ](features/README.md) の手順で確認する。

このチェックアウトに対応する実行可能な観測コマンドの絶対パスを `rpg_cli` に指定し、別のターミナルセッションで起動する。検証用に作った一時ディレクトリを記録する。

```sh
test -x "$rpg_cli" || exit 1
umask 077
rpg_state=$(mktemp -d "${TMPDIR%/}/rpg-live.XXXXXX")
printf '%s\n' "$rpg_state"
"$PWD/macos/MenuBar/build/RuntimeProcessMenuBar.app/Contents/MacOS/RuntimeProcessMenuBar" \
  --cli "$rpg_cli" --scope system --state "$rpg_state/latest.json"
```

## 操作前の読み取り検査

操作前に起動時の記録と `ps -axo pid=,comm=` を照合し、対象が今ビルドした実行ファイルの唯一の個体であることを確認する。専用の `latest.json` で `scope == "system"`、`read_only == true`、`totals.process_count > 0` を確認する。観測が部分的なら、その状態を記録する。起動だけの成功と区別する。認証は不要。

画面操作ツールには今回ビルドした `.app` の絶対パスを指定する。同じアプリ識別子の旧版がある場合は識別子の指定を避ける。実機メニューが取得できない場合はタイムアウト等の結果を残し、画面検証は未確認とする。画面操作ツールが使えず、利用者が操作できる場合は、機能マップの手順を渡し、どこまで確認できたかを聞く。確認結果には利用者による実機操作であることを記す。ログイン設定やアクセシビリティ権限を変更しない。

## 証拠と後片付け

各操作の前後で画面を読み取り、件数、検索語との一致、負荷の数値の順序を確認する。観測状態、操作、合否、観測できた件数だけをリポジトリ外のユーザー専用領域に保存する。生のキャッシュ、プロセス引数、チャット名は証拠へ転記しない。

終了は検証個体のメニューから行う。利用者が操作する間は個体を起動したままにする。画面操作ができない場合は、利用者に検証個体のメニューからの終了を案内する。起動した個体と収集子の終了を確認してから、今回の一時状態だけを消し、証拠が残っていることを確認する。
